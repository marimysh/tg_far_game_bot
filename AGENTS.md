# AGENTS.md — far-bot

Telegram-бот очереди «FAR Помощь» для игрового события. Перенесён с оркестратора n8n на standalone Node.js без зависимостей. Хранилище заявок — Google Таблица, состояние диалогов — локальный JSON-файл.

## Команды

| Команда | Назначение |
|---|---|
| `npm test` | Сценарные тесты на фейковых Telegram/Sheets клиентах (без сети), `tests/run-tests.js` |
| `npm start` | Запуск бота (`node src/index.js`), конфигурация из `.env` |

Требуется Node.js ≥ 20. Бот работает через long polling (`getUpdates`); при старте сам снимает webhook.

## Конфигурация

`.env` создаётся по образцу `.env.example` (секреты живут только на хосте; в репозитории — заглушки). Переменные: `BOT_TOKEN`, `ALLOWED_TOPICS` (список `chatId_threadId` через запятую; `*` — для отладки), `GOOGLE_CLIENT_ID/GOOGLE_CLIENT_SECRET/GOOGLE_REFRESH_TOKEN`, `SPREADSHEET_ID`, `SHEET_NAME` (по умолчанию «Полный список»), `DIGEST_CHAT_ID`/`DIGEST_THREAD_ID`/`DIGEST_POLL_SEC` (пустой `DIGEST_CHAT_ID` отключает дайджест), `STATE_FILE`, `ADMIN_CHAT_ID` (алерты об ошибках).

## Структура

```
src/config.js   загрузка .env
src/tg.js       клиент Bot API: getUpdates-цикл, sendMessage/editMessageText/answerCallbackQuery
src/sheets.js   клиент Google Sheets API: OAuth refresh, values get/append/update
src/state.js    FSM-хранилище в JSON-файле (атомарная запись, TTL состояний 24 ч)
src/queue.js    доменная логика: маппинг строк по ИМЕНАМ колонок из шапки листа,
                actualRows(), appendRequest() (id пишется формулой =ROW()), updateRow()
src/bot.js      роутинг команд и конечный автомат (FSM) диалогов + клавиатуры
src/digest.js   дайджест очереди: поллинг таблицы, отправка при изменении хеша
src/index.js    сборка, логирование, alertAdmin, точка входа
tests/          фейковые клиенты + сценарии (33 проверки)
scripts/        make-test-sheet.js — создание тестовой копии таблицы
deploy/         systemd unit (шаблон: поправьте пользователя и пути под хост)
```

## Правила, важные для изменений

1. **Никаких секретов в репозитории** — только заглушки в `.env.example`. Токен бота и Google OAuth — на хосте (.env / EnvironmentFile, права 600).
2. **Маппинг колонок таблицы — только по именам** из шапки листа; порядок колонок в листе исторически не совпадает с порядком полей в коде и может меняться.
3. Числовые поля (`id`, `Изначально`, `Порог в днях`, `Осталось дней`) приводятся к числу; нечисловой ввод дней отклоняется с повтором шага (и в `/farcreate`, и в `/farupdate`).
4. **Таймзона процесса — Europe/Moscow (`TZ`)**: даты и ISO-таймстемпы пишутся с офсетом +03:00 (как в исходной реализации). С другой таймзоной сломается сортировка дайджеста и даты создания заявок вокруг полуночи.
5. Пороги показа заявок: Стройка — 7 дней, Исследование — 1 (`typeThresholds` в config.js).
6. Дайджест шлётся только при изменении содержимого очереди (хеш), а не при любом изменении листа.
7. `state.json` и `*.tmp` не коммитить.

## Намеренные отличия от исходной реализации

- Ввод дней в `/farupdate` валидируется на число (раньше записывался любой текст).
- Команда, присланная в середине диалога, считается ответом текущего шага, а не исполняется параллельно с ним.
- Пустой дайджест не отправляется; сообщения из неразрешённых чатов игнорируются молча.

## Деплой

`deploy/far-bot.service` — шаблон systemd unit: подставьте пользователя хоста и пути (каталог приложения, бинарник Node.js ≥ 20), EnvironmentFile с `.env` (права 600). Откат: остановить сервис и вернуть прежнюю реализацию бота.
